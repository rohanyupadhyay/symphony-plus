# Quickstart: Validate the Symphony Plus Rename

## Prerequisites

- Work from the GH-18 issue branch in its isolated workspace.
- Use the repository-supported Elixir 1.19/OTP 28 environment through `mise`.
- Do not place real credentials in commands, logs, fixtures, or committed files.

## 1. Validate canonical operator contracts

From the repository root, inspect the renamed workflow assets and command documentation:

```bash
test -f .symphony-plus/WORKFLOW.md
test -f .symphony-plus/README.md
test ! -e .symphony
rg -n '/symphony-plus|symphony-plus/' .symphony-plus elixir/docs elixir/examples
```

Expected: maintained examples use `/symphony-plus`, `symphony-plus/`, and `.symphony-plus/`; legacy paths are absent.

## 2. Build and exercise the renamed executable

```bash
cd elixir
mise exec -- mix setup
mise exec -- mix build
test -x bin/symphony-plus
mise exec -- ./bin/symphony-plus --help
```

Expected: the executable and help/banner text identify Symphony Plus; `bin/symphony` is not produced as an alias.

## 3. Run focused rename and lifecycle tests

Run the targeted suites generated by the implementation tasks for CLI/release naming, GitHub workflow control and launcher behavior, quota persistence, log naming, dashboard text, and startup/recovery behavior. Exact test paths are defined in `tasks.md` after task generation.

Expected: renamed boundaries pass without changing dispatch, retry, reconciliation, cancellation, cleanup, automatic review, or merge-queue semantics.

## 4. Run the complete quality gate

```bash
make -C elixir all
```

Expected: formatting, specs, Credo, coverage, and Dialyzer pass.

## 5. Audit legacy names and paths

```bash
rg -n --hidden -g '!.git/**' -g '!elixir/deps/**' -g '!elixir/_build/**' -e '\bSymphony\b' -e '\bsymphony\b' .
find . -path './.git' -prune -o -iname '*symphony*' -print
```

Expected: every remaining legacy whole-word occurrence is explicitly classifiable as the upstream OpenAI Symphony project or an immutable external identifier. Repository-controlled paths and names use Symphony Plus forms. The feature specification directory itself is expected to contain the descriptive phrase `rename-symphony-plus` and is not a runtime interface.

## 6. Validate GitHub metadata at the safe handoff

Use the host-mediated GitHub API to confirm the label was renamed in place from `symphony` to `symphony-plus` and remains attached to the managed issue/PR as required. Do not rename it early enough to interrupt the active durable workflow.

## 7. Review the diff

Confirm there are no credentials, unrelated refactors, generated build outputs, accidental edits to upstream URLs, unsupported compatibility aliases, or unexplained legacy occurrences. Compare the implemented interface values with [contracts/naming-contract.md](contracts/naming-contract.md).
